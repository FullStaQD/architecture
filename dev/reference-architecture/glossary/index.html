Glossary

The Glossary provides descriptions of the terminology used throughout this documentation. This is particularly important because some terms are ambiguous, with different meanings depending on the context or stakeholders involved. Given the diversity of stakeholders in the quantum computing domain, the Glossary aims to clarify these terms to establish a common understanding, and improve consistency throughout the documentation.

Quantum Processing Unit (QPU)

Quantum computers are sometimes referred to as quantum processing units (QPUs) to emphasise their role as a specialised processing unit that is part of a larger system. In these larger systems, QPUs can be used to offload quantum computation tasks which are otherwise expensive to solve on a CPU. QPUs therefore function as accelerators, similarly to how graphics processing units (GPUs) can be used to offload image processing tasks like matrix multiplications. This accelerator perspective is often taken in the context of quantum software system deployments such as high-performance computing centres.

Quantum Kernel

A quantum kernel is a program to be executed on a quantum computer. The term highlights that the kernel program is part of a bigger program which is executed across heterogeneous hardware (meaning there might be CPUs, GPUs, QPUs or other types of processors involved).

See also:

  • GPU Kernels in the CUDA Programming Language

Quantum Error Correction

Info

In the FullStaQD reference architecture, QEC is discussed in the fault tolerance section.

Quantum Error Correction (QEC) uses redundancy to detect and correct errors occuring throughout quantum computation. Logical qubits are encoded across multiple physical qubits, allowing errors to be detected by measuring whether the redundancies are still intact. Detected errors can subsequently be corrected while preserving the encoded quantum information. QEC therefore introduces a substantial resource overhead, but is the fundamental approach towards fault-tolerant quantum computation (FTQC), as sufficiently low physical error rates can, theoretically, be suppressed to arbitrarily low logical error rates through fault-tolerant error correction.

See also:

  • IBM Quantum Blog for an accessible overview of QEC, QES and QEM
  • Nielsen and Chuang as well as Terhal for further background on the fundamentals of QEC
  • Google's recent Nature publication on Quantum error correction below the surface code
  • IBM Tutorial for practical foundations of QEC

Quantum Error Suppression

Info

In the FullStaQD reference architecture, QES is discussed in the fault tolerance section.

Quantum Error Suppression (QES) aims to reduce errors at or close to their physical source by exploiting prior knowledge about unwanted hardware effects like noise. Instead of correcting errors after they have occurred, suppression techniques modify the hardware control to prevent, or reduce their impact, for example through techniques such as dynamical decoupling. QES can therefore improve the reliability of quantum operations with comparatively low resource overhead but its effectiveness is limited by the type of noise and available control resources, and residual errors can accumulate over time.

See also:

  • Ezzell et al. for a survey of different dynamical decoupling approaches and their performance
  • Viola et al. for the underlying principles

Quantum Error Mitigation

Info

In the FullStaQD reference architecture, QEM is discussed in the fault tolerance section.

Quantum Error Mitigation (QEM) reduces the effect of noise on computational results. It typically combines multiple noisy circuit executions with classical post-processing to estimate expectation values that are closer to their ideal, noise-free values. Common techniques include Zero Noise Extrapolation (ZNE) and Probabilistic Error Cancellation (PEC); however, these methods can incur substantial sampling overhead.

See also:

  • Li and Benjamin as well as Temme et al. for more information about foundational approaches to QEM
  • van den Berg et al. for a recent development of PEC towards larger quantum processors

Quantum Programming Language (QPL)

In the context of the FullStaQD Reference Architecture, we use the term Quantum Programming Language to describe quantum program specification formats with typical features of programming languages. Such features include for example control flow which could allow a quantum program to use the result of a mid-circuit measurement to decide which gate to apply next. We also use the term QPL to emphasise that a program can be compiled and does not rely on the execution within a host language.

In the Building Block View, QPLs are discussed as a possible interface between the System Layer and the Application Layer.

Cross-Layer Concerns

In the wider FullStaQD project, there is a Cross-Layer Concerns working package with various responsibilities that do not fit within a single layer. In the FullStaQD Reference Architecture, the cross-layer tools from this working package are discussed in the Cross-Cutting Concepts section.

Why pick a different name?

The use of the term Cross-Layer Concerns in a FullStaQD working package could have made it an obvious choice for the Cross-Cutting Concepts section in this documentation. However, the associated working package also carries responsibilities that go beyond architectural considerations. For the FullStaQD Reference Architecture documentation, we therefore chose to stick to the term Cross-Cutting Concepts which is suggested by the arc42 architecture documentation template that we follow.
